###################
GIS Developer Guide
###################

The GIS communicates to the outside via a Modbus server running off of the main GIS Pilz CPU.
The software uses pymodbus as the Modbus library.
The GIS publishes 35 holding registers, with one 16-bit register per subsystem entry in ``lsst.ts.gis.subsystem_order``.
Register bits are decoded in Pilz least-significant-bit first order.
The PLC ``Send_TCS`` structured text can be parsed with ``bin/generate_register_map`` to create an audit map from Modbus words and bits to PLC expressions.
``Send_TCS.txt`` is treated as a manually supplied reference input, not as runtime authority.

.. _Simulator:

Simulator
=========

Simulation mode starts a local pymodbus simulator using ``python/lsst/ts/gis/data/setup.json``.
The CSC creates a temporary simulator JSON file at startup so that the Modbus and simulator HTTP ports can be chosen dynamically for tests.
The temporary simulator JSON file is removed when the CSC leaves an active state or shuts down.

The test configuration still contains the real GIS Modbus endpoint.
In simulation mode the CSC rewrites the relevant connection values so that the commander reaches the local simulator instead of real hardware.
When exercising the tunnel lifecycle in simulation, the simulated tunnel should forward from a local tunnel port to the local pymodbus simulator port.
This allows tests to exercise the commander tunnel lifecycle while keeping all network traffic local.

Register Map Audit Tool
=======================

The ``bin/generate_register_map`` command parses a manually supplied ``Send_TCS.txt`` file from the repository root and renders a Python representation of the PLC-to-Modbus mapping.
This is intended for audits and reviews of the GIS register mapping.
Because ``Send_TCS.txt`` is not automatically exported from the PLC project, generated maps should not be treated as proof that the deployed controller is up to date.

The parser tests skip the full-file checks when ``Send_TCS.txt`` is not present.
Parser behavior that does not depend on the PLC export is still tested with inline fixtures.
